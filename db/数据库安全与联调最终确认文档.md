## 三、 安全规范与 Git 红线（务必严格执行）

为了防止公开仓库泄露数据库密码，请前端和后端团队共同遵守以下规范：

> **1. 在代码里引用环境变量**：统一使用 `${DB_PASSWORD}` 等占位符进行配置。
> **2. 本地创建配置文件**：在本地创建 `.env` 文件（或 `application-local.yml`），将真实密码写进本地文件中。
> **3. 严格配置 `.gitignore`**：确保 `.env` 和 `application-local.yml` 等本地敏感配置文件已被 `.gitignore` 忽略，**严禁提交至 GitHub**。
> **4. 配置模板使用占位符**：若需提交配置文件模板（如 `application.yml.example`），密码字段必须使用占位符（如 `your_password`）。
> **5. 责任声明**：若因未遵守上述规范导致密码泄露，将直接影响课设评分，并可能引发数据库被恶意入侵的安全风险。请各位组员务必高度重视。

## 四、 最新数据库结构变更通知

1. **新增字段**：`orders` 表已新增 `shipping_address`（收货地址，交易快照，下单后不随用户资料改变）。
2. **新增表**：`goods_image`（支持多图）、`favorite`（支持收藏）。
3. **新增触发器**：见 `db/03_triggers.sql`（订单完成自动售出、封禁用户自动下架、拦截未完成订单评价）。后端 Service 层严禁重复编写相关更新逻辑，以免产生冲突。

## 五、 联调与测试约定

1. **接口测试**：后端已提供 `backend/requests/secondhand.postman_collection.json`，可直接导入 Postman / Apifox 进行测试。注意先 `GET /api/auth/csrf` 获取 Token，并在写请求中携带。
2. **并发测试**：真实 MySQL 执行、并发与事务回滚待 DBA 环境验收。两人可同时用 Postman 测试同一商品的并发下单，验证“防超卖”逻辑。
3. **数据口径**：商品状态（0-4）与订单状态（0-5）必须以数据库为准，严禁使用字符串。具体见《前端确认文档- DBA测试员答复版》。
4. **需求变更**：任何字段/表结构的改动，必须先经过 DBA（测试员）评估并修改 SQL 基线，前后端不得私自新增字段。
