# 后端 API 端点 404 阻塞问题确认单

> **提交人**：DBA / 测试员
> **提交时间**：2026-09-10
> **优先级**：🚨 **最高（全组端到端联调唯一阻塞点）**

## 一、 问题现象

在真实数据库环境已就绪、前端已跑通的前提下，后端接口无法正常访问：
1. **浏览器/Postman 访问**：`GET http://localhost:8080/api/health` 返回 **404 Not Found**（HTTP 状态码为 404，而非连接拒绝，说明 8080 端口连通，但服务端找不到该路径）。
2. **前端控制台表现**：前端页面发起的 `GET /api/auth/csrf`、`GET /api/categories`、`GET /api/goods` 等请求，均在 Network 面板返回 404。
3. **前端现状**：前端已完成全部改造，纯前端逻辑（路由守卫、表单校验、主题切换、本地图片加载）已通过测试（详见《前端独立测试结果报告》），目前因后端接口不可用而无法进行全流程联调。

## 二、 DBA/测试员已完成的排查

为避免误报，我已在我方环境进行过以下确认：
1. **MySQL 服务已启动**：本地数据库 `secondhand`（MySQL 8.0.44）处于运行状态，包含完整的表结构、约束、触发器及清洗后的高质量测试数据。
2. **网络与端口连通**：8080 端口是通的（接口返回了 HTTP 404 响应，而不是 `Connection Refused`），说明后端 Spring Boot 应用已经启动。
3. **环境信息已提供**：后端所需数据库连接串（`jdbc:mysql://localhost:3306/secondhand?connectionTimeZone=Asia/Shanghai...`）和密码已通过私聊发给后端开发人员，且已确认数据库账号权限正常。

## 三、 建议后端排查方向（请逐项核对）

目前最可能导致“端口通、全 404”的原因有以下三点，请后端逐一核实：

1. **确认是否使用了 `mysql` 运行模式（最可能的原因）**
   * 若后端以 `local` 模式启动，业务接口（auth、goods、categories 等）是被刻意屏蔽/不装配的，会直接导致全部业务请求返回 404。
   * **正确启动命令**：`mvn spring-boot:run "-Dspring-boot.run.profiles=mysql"`
2. **确认数据库连接是否真正成功**
   * 请检查环境变量 `DB_URL`、`DB_USERNAME`、`DB_PASSWORD` 是否正确无误。
   * 请检查启动日志（Console）中是否有关于 `DataSource` 或 `MyBatis Mapper` 加载失败的报错。如果数据库连接失败，Spring Boot 可能未能完整启动或没有注册 Controller。
3. **确认 `api/health` 接口实现是否存在**
   * 请检查对应的 Controller 里 `@RequestMapping` 或 `@GetMapping` 的路径是否正确写成了 `/api/health`。
   * 若项目依赖 Spring Boot Actuator，默认路径为 `/actuator/health`，若需改为 `/api/health`，请检查配置是否遗漏。
