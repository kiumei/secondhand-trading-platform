# 校园二手交易平台 · 前端实现情况

> 本文档说明前端当前的实现状态，并与数据库（`db/secondhand_full.sql`）及后端对齐基线（`docs/dba确认文档.md`）做对照。
> 当前前端为**纯前端 mock 阶段**：数据存 localStorage，接口签名、字段名、状态码均已按可无缝替换真实后端的方式设计对齐。

## 一、技术栈

| 层 | 技术 |
|----|------|
| 框架 | Vue 3.5 |
| 构建工具 | Vite |
| 状态管理 | Pinia 4 |
| 路由 | Vue Router |
| UI 组件库 | Element Plus |
| 富文本编辑器 | wangEditor 5 |
| 语言 | TypeScript |
| 后端（规划） | Spring Boot + MyBatis + MySQL |

## 二、已实现功能

### 1. 用户体系（sys_user）

- 手机号登录 / 注册（登录态 1 天有效期，存 localStorage）
- 角色区分：学生(0) / 管理员(1)，路由守卫按角色控制权限
- 封禁 / 解封用户（封禁后自动将其商品下架，对齐触发器 `trg_user_ban_off_goods`）
- 管理员重置用户密码
- 个人资料编辑（昵称 / 简介 / 收货地址，收货地址带校区联想）、修改密码
- 用户个人主页：头像、简介、统计（在售 / 评价 / 评分）、联系方式（手机号 + 收货地址）、在售商品、收到的评价

### 2. 商品分类（category）

- 两级分类：4 个实物父类 × 2 子类
  - 学习考试：教材文具 / 书籍资料
  - 数码装备：手机电脑 / 数码配件
  - 宿舍生活：宿舍用品 / 日常个护
  - 穿搭休闲：运动服饰 / 零食美妆

### 3. 商品（goods）

- 发布商品：圆形主图预览、多图上传（最多 4 张）、名称字数计数、两级级联分类、成色等级、价格 / 原价、交易方式（1邮寄 / 2自提 / 3两者）、富文本详情
- 字段对齐后端口径：`goodsId / publishUserId / cateId / title / sellPrice / originalPrice / tradeType / goodsDesc / qualityLevel / rejectReason / publishTime / goodsStatus / sellerName / cateName / purchasable`
- 商品状态码：`0待审核 / 1上架 / 2下架 / 3已售出 / 4驳回`
- 浏览 / 搜索 / 筛选 / 排序（综合 / 最新 / 价格）
- 前端私货字段：图片（压缩 base64）、浏览量 `views`

### 4. 订单（orders）

- 完整订单流：下单 → 待付款 → 待发货 → 待收货 → 已完成（另有取消态）
- 订单状态码：`0待付款 / 1待发货 / 2待收货 / 3完成 / 4取消 / 5售后`
- 下单确认弹窗：显示商品 / 价格 / 收货人昵称 / 收货地址（可改）
- 收货地址快照 `shippingAddress`（下单后不变），待付款订单可修改地址
- 取消订单（取消后商品恢复可购买）；订单完成自动把商品置为已售（对齐触发器 `trg_order_complete_update_goods`）
- 订单列表显示交易对方昵称；状态变更自动通知对方

### 5. 评价（evaluate）

- 评分（1-5 星）+ 文字评价
- 评价绑定真实已完成订单，同一订单仅可评价一次（对齐唯一约束 + 触发器 `trg_prevent_unfinished_evaluate`）
- 商品详情页、用户主页展示评价

### 6. 私信（message）

- 会话列表 + 聊天窗口，发送文字和图片消息
- 消息已读标记（未读角标，读后消失）

### 7. 举报（report）

- 商品详情页举报（举报类型 + 举报原因）
- 管理员举报处理（填写处理结果）

### 8. 管理员功能

- 仪表盘：商品 / 用户 / 订单 / 举报 / 销售额统计 + 待审核商品列表（跳审核）
- 商品审核：编辑 / 通过 / 驳回（+原因）/ 下架
- 分类管理：两级增删改（新增可选父类、编辑重命名、删除）
- 用户管理（封禁 / 解封 / 重置密码）、举报处理、评价管理、订单管理

### 9. 其他

- 首页三栏布局、分类推荐卡片、Banner、精选好物
- 收藏
- 主题切换（浅色 / 深色 / 跟随系统）
- 收货地址联想数据（南昌大学全校区建筑 + 快递站点）

## 三、与数据库 / 后端对齐情况

字段名、状态码、业务规则已基本对齐（见「二」）。当前仍属 mock 阶段的差异如下：

| 项 | 后端 / 数据库 | 前端 mock 现状 | 说明 |
|----|--------------|--------------|------|
| 登录认证 | Cookie Session + CSRF | localStorage 存 user 对象 | 接后端时切换 |
| 商品图片 | 上传接口 + `goods_image` 表 | 压缩 base64 存 localStorage | 接后端时走上传接口 |
| 私信图片 | 图片 URL（方案 1 存 content） | 压缩 base64 存 `image` 字段 | 接后端时 URL 存 content |
| 浏览量 | 无字段 | 前端私货 `views` | 接后端后决定是否保留 |

## 四、当前架构

- 数据访问统一走 `src/api/`，mock 实现（localStorage 持久化 + 模拟延迟），接口签名与真实后端一致，接后端时只需替换实现、不改调用方
- 数据带版本号，seed 结构变化时旧数据自动重置
- 分类常量见 `src/constants/categories.ts`，收货地址联想数据见 `src/constants/locations.ts`

## 五、待办（接后端时处理）

1. 搭建 HTTP 请求层 + Vite `/api` 代理，接入 **Session/CSRF 认证** 与手机号登录 / 注册
2. 商品图 / 私信图对接上传接口（`POST /api/uploads/images`）
3. 各模块接口逐个替换 mock 实现（分类 → 商品 → 订单 → 评价 → 私信 → 举报）
4. 处理前端私货字段（浏览量、图片 base64）在后端化后的取舍
