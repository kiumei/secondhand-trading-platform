# 校园二手交易平台 · 前端实现情况

> 本文档说明前端当前的实现状态，并与数据库设计文档（`docs/SecondHandTrasaction/README.md`）做对照。
> 当前前端为**纯前端 mock 阶段**：数据存 localStorage，接口签名按可无缝替换真实后端的方式设计。

## 一、技术栈

| 层 | 技术 |
|----|------|
| 框架 | Vue 3.5 |
| 构建工具 | Vite |
| 状态管理 | Pinia 4 |
| 路由 | Vue Router |
| UI 组件库 | Element Plus |
| 富文本编辑器 | wangEditor 5 |
| 语言 | TypeScript |
| 后端（规划） | Spring Boot + MyBatis + MySQL |

## 二、已实现功能

### 1. 用户体系（sys_user）

- 注册 / 登录（登录态 1 天有效期，存 localStorage）
- 角色区分：学生 / 管理员，路由守卫按角色控制权限
- 封禁 / 解封用户（被封禁用户无法登录）
- 管理员重置用户密码
- 个人资料编辑、修改密码
- 用户个人主页：头像、简介、统计（在售 / 评价 / 评分）、联系方式、在售商品、收到的评价

### 2. 商品分类（category）

- 两级分类：4 个实物父类 × 2 子类
  - 学习考试：教材文具 / 书籍资料
  - 数码装备：手机电脑 / 数码配件
  - 宿舍生活：宿舍用品 / 日常个护
  - 穿搭休闲：运动服饰 / 零食美妆
- 校园服务独立入口：技能服务 / 回收（通过 Dock 栏进入）

### 3. 商品（goods）

- 发布商品：圆形主图预览、多图上传（最多 4 张）、名称字数计数、分类两级级联、成色标签组、价格/原价、富文本详情、所在地级联选择
- 商品字段：名称、售价、原价、描述（富文本）、成色等级、驳回原因、发布时间、商品状态（5 态）
- 额外字段：多图、所在地（校园地点）、浏览量、想要数、包邮、卖家名
- 浏览 / 搜索 / 排序（综合 / 最新 / 价格 / 最想要）

### 4. 订单（orders）

- 完整订单流：下单 → 待支付 → 已支付 → 已发货 → 已完成（另有已取消态）
- 订单详情弹窗（买卖双方电话 / 地址）
- 状态变更自动通知对方（发货通知买家、确认收货通知卖家）

### 5. 评价（evaluate）

- 评分（1-5 星）+ 文字评价
- 商品详情页、用户主页展示评价

### 6. 私信（message）

- 会话列表 + 聊天窗口
- 发送文字 + 图片
- 在线状态提示（头像绿点 / 灰点）
- 新建会话入口

### 7. 举报（report）

- 商品详情页举报（填原因）
- 管理员举报处理

### 8. 管理员功能

- 仪表盘（商品数 / 用户数 / 订单数 / 销售额统计）
- 商品审核（通过 / 驳回 + 原因 / 下架）
- 分类管理、用户管理、举报处理、公告管理、评价管理、订单管理、系统设置

### 9. 其他

- 首页三栏布局、分类推荐卡片、Banner、精选好物
- 收藏
- 主题切换（浅色 / 深色 / 跟随系统）
- 初始化向导（外观 / 站点信息 / 管理员账号 / 首页配置 / SMTP）
- 校园地点数据（南昌大学全校区建筑 + 快递站点）

## 三、与数据库设计文档的差距

| 项 | 文档设计 | 前端现状 | 说明 |
|----|---------|---------|------|
| 用户注册时间 | 有 `register_time` | 无 | 需补字段 |
| 分类描述 | 有 `cate_desc` | 无 | 需补字段 |
| 分类层级 | 单层 | 两级 | 前端扩展，接后端需对齐 |
| 私信已读 | 有 `is_read` | 无 | 列表只有总数，无未读角标 |
| 举报类型 | 有 `report_type` | 无 | 只有原因 |
| 举报证据图片 | 有 `proof_img` | 无 | 缺 |
| 举报处理结果 | 有 `handle_result` | 无 | 只有处理状态 |
| 订单状态 | 0未支付 / 1已支付 | 5 态（含物流/签收/取消） | 前端更细，接后端需对齐 |
| 评价关联订单 | 有 `order_id` | 写评价时传 0 | 未真正绑定订单 |
| 交易方式 | 有 `trade_type` | 用 sell/want 近似 | 语义不完全对应 |

## 四、当前架构

- 数据访问统一走 `src/api/`，mock 实现（localStorage 持久化 + 模拟延迟），接口签名与真实 axios 调用一致，接后端时只需替换实现、不改调用方
- 数据带版本号，seed 结构变化时旧数据自动重置
- 分类常量见 `src/constants/categories.ts`，地点数据见 `src/constants/locations.ts`

3. 对齐订单状态、交易方式字段
4. 评价绑定订单
