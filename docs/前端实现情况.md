# 校园二手交易平台 · 前端实现情况

> 本文档说明前端当前的实现状态，并与数据库（`db/secondhand_full.sql`）及后端对齐基线（`docs/dba确认文档.md`）做对照。
> 当前前端**已全部接真实后端**（Cookie Session + CSRF，axios 请求层），字段名、状态码、类型均已对齐后端契约。

## 一、技术栈

| 层 | 技术 |
|----|------|
| 框架 | Vue 3.5 |
| 构建工具 | Vite |
| 状态管理 | Pinia 4 |
| 路由 | Vue Router |
| UI 组件库 | Element Plus |
| 富文本编辑器 | wangEditor 5 |
| HTTP 客户端 | axios |
| 语言 | TypeScript |
| 后端 | Spring Boot + MyBatis + MySQL |

## 二、已实现功能（均接真实后端）

### 1. 用户体系（sys_user）

- 手机号登录 / 注册（Cookie Session + CSRF）
- 角色区分：学生(0) / 管理员(1)，路由守卫按角色控制权限
- 管理员封禁 / 解封（`POST /admin/users/{id}/ban|unban`）、重置密码（`POST /admin/users/{id}/reset-password`）
- 个人资料编辑（昵称 / 简介 / 收货地址，收货地址带校区联想）、修改密码
- 用户个人主页：公开用户资料（`GET /public/users/{id}`，仅 userId/userName/avatar/intro）、在售商品、收到的评价

### 2. 商品分类（category）

- 单级 6 分类（来自 `GET /categories`）：教材教辅 / 数码产品 / 生活用品 / 宿舍家具 / 运动器材 / 服饰鞋包
- 管理员分类管理：新增 / 编辑 / 删除

### 3. 商品（goods）

- 发布商品：主图 + 多图（最多 4 张，上传走 `POST /uploads/images` 拿 URL）、单级分类、成色等级、价格/原价、交易方式（1邮寄/2自提/3两者）、富文本详情
- 图片上传前先在前端压缩（最长边 800px JPEG）再传，避免原图超过后端 multipart 上限导致 Network Error；发布/提交中表单全屏 loading
- 字段对齐后端口径：`goodsId / publishUserId / cateId / title / sellPrice / originalPrice / tradeType / goodsDesc / qualityLevel / rejectReason / publishTime / goodsStatus / sellerName / cateName / coverUrl / purchasable`
- 商品状态码：`0待审核 / 1上架 / 2下架 / 3已售出 / 4驳回`
- 列表 / 详情 / 我的商品 / 浏览 / 搜索 / 筛选 / 排序
- 首页 / 搜索等购物入口只展示 `purchasable`（上架且无有效订单）的商品，已被拍下 / 已售的商品不再出现在列表

### 4. 订单（orders）

- 完整订单流：下单 → 待付款 → 待发货 → 待收货 → 已完成（另有取消态）
- 订单状态码：`0待付款 / 1待发货 / 2待收货 / 3完成 / 4取消 / 5售后`
- 下单确认弹窗：显示商品 / 价格 / 收货人昵称 / 收货地址
- 收货地址快照 `shippingAddress`（下单后不变）
- 支付 / 发货 / 收货 / 取消（`POST /orders/{id}/mock-pay|deliver|complete|cancel`）

### 5. 评价（evaluate）

- 评分（1-5 星）+ 文字评价（`POST /orders/{id}/evaluation`）
- 评价绑定已完成订单，同一订单仅可评价一次（后端唯一约束 + 触发器兜底）
- 商品详情、用户主页、管理员评价列表

### 6. 私信（message）

- 会话列表 + 聊天窗口，发送文字和图片消息
- 图片消息：URL 存 `content`（`/api/media/` 或 http 开头识别为图片）
- 消息已读标记（`PATCH /messages/{id}/read`）
- 会话按最新一条消息倒序置顶，带未读红点；聊天记录按时间正序展示（最老上、最新下），自动贴底滚动（正在往上翻历史不被轮询拉回）
- 点开某会话即标记已读并清其红点，同时广播 `messages-read` 事件即时刷新右下角 DockBar「消息」角标（无需切换路由）
- 过滤"发给自己"的系统通知（`sendUserId === receiveUserId`），并禁止给自己发消息，避免产生垃圾自聊
- 消息实时性为 **3 秒轮询**；联调多账号时请**一个浏览器只登一个账号**（Cookie Session 会互相顶，出现串号）

### 7. 举报（report）

- 商品详情页举报（举报类型 1-5 + 举报原因）
- 管理员举报处理（填写处理结果）

### 8. 管理员功能

- 仪表盘：商品 / 用户 / 订单 / 举报 / 销售额统计 + 待审核商品列表（走管理员接口按 0-4 状态拉全量，待审核数据与统计准确）
- 商品审核：编辑 / 通过 / 驳回（+原因）/ 下架（审核页读取待审核列表，而非公开接口）
- 分类管理、用户管理（封禁 / 解封 / 重置密码）、举报处理、评价管理、订单管理
- 各后台列表页与仪表盘均有 loading 指示

### 9. 其他

- 首页三栏布局、分类推荐卡片、Banner、精选好物
- 收藏（`GET/POST/DELETE /favorites`）
- 主题切换（浅色 / 深色 / 跟随系统）；深色模式下 wangEditor 富文本编辑区文字提亮、背景压暗，避免看不清
- 收货地址联想数据（南昌大学全校区建筑 + 快递站点，前端本地）

## 三、与后端对齐情况

字段名、状态码、业务规则、认证方式已全部对齐，无 mock 残留差异。主要契约：

- ID 用 string（varchar 32）；金额前端内部 number、HTTP 传输 string
- 商品状态 `0待审核/1上架/2下架/3已售出/4驳回`；订单 `0待付款/1待发货/2待收货/3完成/4取消/5售后`
- 认证 Cookie Session + CSRF，写请求带 `X-CSRF-TOKEN`

## 四、当前架构

- 数据访问统一走 `src/api/`，全部为 axios HTTP 实现（`src/api/http.ts` 封装 CSRF、`{code,message,data}` 解包、统一错误拦截）
- CSRF：恢复会话（页面刷新后）先重取 token；写请求遇 403 自动「重取 token 并重试一次」（登录后 token 会被后端轮换，旧 token 必 403）
- 分页取全量用 `getAllPages`：后端 `pageSize` 上限 **50**，传 100/200 会整批被拒（收藏 / 私信 / 用户 / 管理员列表均受此约束）
- Vite `/api` 代理到后端 8080
- 收货地址联想数据见 `src/constants/locations.ts`（前端本地）
- 旧的 mock 数据层（`src/api/mock/`）已不再使用，可清理

## 五、剩余事项（收尾）

1. **删除 mock 数据层**：`src/api/mock/db.ts` 及其引用已无业务用途，可删除
2. **删除前端私货字段**：`views`（浏览量）数据库无此字段，`toGoods` 里目前写死为 0，可彻底移除
3. **前端模拟触发器逻辑**：订单完成置已售、封禁下架等逻辑当前在 mock 里，接后端后由数据库触发器兜底（前端不再自己写这些状态变更，已通过后端接口实现）
4. **公开用户资料不含手机号/地址/角色**：后端有意不暴露，个人主页这几项显示为空，需后端加字段或前端隐藏
5. **商品图/头像多为外网图床或随机字符串**：后端 seed 数据问题，需 DBA 换真实图
6. **端到端联调**：走通「注册→发布→审核→购买→支付→发货→收货→评价」全流程 + 管理员审核/封禁/举报处理
