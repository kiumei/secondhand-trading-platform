## 二、 接真实后端前必须处理的问题（重点提醒，否则联调必报错）

### 问题1：前端“浏览量 views”字段
- **数据库现状**：数据库 `goods` 表无 `views` 字段。
- **建议处理**：接后端时**直接删除**前端私货字段 `views`。如必须保留，需走流程找 DBA 新增字段。

### 问题2：图片 Base64 问题（极其重要！）
- **数据库现状**：商品图片必须走 `goods_image` 表，存储的是图片 **URL**（`varchar` 类型）；私信图片也是 URL。
- **建议处理**：接后端时，**严禁将压缩 Base64 字符串直接传给后端！** 必须先调用后端的 `POST /api/uploads/images` 接口，拿到后端返回的图片 URL，再将 URL 存入 `goods_image` 表中。私信图片同理（放入 `message.content` 的 URL）。

### 问题3：前端模拟触发器逻辑必须删除（防止重复执行）
- **数据库现状**：数据库已通过触发器自动完成以下动作：
  - 订单完成 (`order_status=3`) -> 自动将商品置为已售 (`goods_status=3`)。
  - 用户封禁 (`status=1`) -> 自动将该用户商品全部下架 (`goods_status=2`)。
  - 拦截未完成订单的评价。
- **建议处理**：前端 mock 阶段自己写的模拟逻辑，接后端后**必须全部删除**！逻辑由数据库触发器兜底，前端只负责调接口，千万不要再自己写一遍状态变更，否则会造成双重执行、事务报错，甚至数据错乱。

### 问题4：认证方式切换（localStorage -> Cookie Session + CSRF）
- **数据库现状**：后端采用 Spring Security + Cookie Session，要求所有写请求携带 CSRF Token。
- **建议处理**：
  - 接后端时，前端需搭建 HTTP 请求层（`axios` 或 `fetch`），配置 `Vite /api` 代理。
  - 在登录前，先调用 `GET /api/auth/csrf` 获取 Token，并将返回的 `headerName` 和 `token` 保存在全局变量里。
  - **注意**：登录成功后 Token 会刷新，需要重新获取！请务必处理好 401（未登录）、403（缺少 Token 或越权）、409（状态冲突）等错误码的统一拦截和提示。

### 问题5：字段名大小写/下划线问题
- 后端返回 JSON 时，字段通常是 **驼峰命名**（如 `shippingAddress`）。请前端统一下列字段的映射：
  - 收货地址：`shippingAddress`
  - 商品状态：`goodsStatus`
  - 订单状态：`orderStatus`
  - 交易方式：`tradeType`
